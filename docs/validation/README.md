# Proof 0 validation package

This package is for testing whether organizations will pay for a Digital Estate
Assessment outcome before Contexla invests heavily in platform implementation.

The test is not whether people like the platform vision. It is whether a buyer
with an active trigger will provide evidence, commit time, and pay for a useful
assessment.

## Working sequence

1. Use the [offer](offer.md) to describe the outcome in buyer language.
2. Run the [discovery interview](discovery-interview.md) without leading with a
   platform demonstration.
3. Record every conversation in the [scorecard](scorecard.md).
4. When a qualified buyer exists, propose the bounded [paid pilot](pilot.md).
5. Tailor the [evidence request](evidence-checklist.md) to the approved scope.
6. Deliver findings using the [report outline](report-outline.md).
7. Record which collection, normalization, and analysis steps repeated. Those
   repetitions become candidates for the first product automation.

## Proof 0 exit criteria

Proceed to substantial platform implementation when at least one of these is
true:

- a customer pays for the pilot and accepts the proposed evidence and output;
- a design partner commits access, staff time, a defined decision date, and a
  credible path to payment;
- two independent qualified buyers confirm substantially the same trigger,
  evidence needs, and decision-making output.

A paid pilot is the preferred signal. Compliments, LinkedIn engagement, broad
interest in AI, or requests for a free demonstration do not satisfy the proof.

## What can be built during Proof 0

Small tools are appropriate when they directly help deliver a live pilot, such
as a customer-run inventory script, snapshot schema, report generator, or
deterministic analyzer. Avoid building authentication, agent orchestration,
marketplaces, a universal Connector SDK, or a polished platform shell before a
real engagement requires them.
